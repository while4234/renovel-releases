# 章节与场景新增字数预算

“加料字数”均指相对原文的新增字数。项目创建向导和项目配置使用相同规则：

| 配置 | 范围与默认值 | 含义 |
| --- | --- | --- |
| 章节计划加料总字数 T | 300～20000；沿用已有值 | 每章独立分配的初始总预算 |
| 每场景最低加料字数 M | 0～20000；默认 150 | 低于此值则补足；0 关闭保底 |
| 每场景最高加料字数 X | 0～20000；默认 0 | 高于此值则限额；0 不限制上限 |

启用上限时必须满足 X ≥ M。场景指合并重叠识别结果后的实际改写窗口。

模型先为每个窗口分配非负整数 aᵢ，且总和为 T。后端统一计算：

```text
bᵢ = max(aᵢ, M)                   X = 0
bᵢ = min(max(aᵢ, M), X)           X > 0
E = Σbᵢ
```

调整后不向其他场景转移预算，也不重新缩放到 T。T=1000、十个场景各分100、M=150，最终 E=1500；T=1500、单场景、X=700，最终 E=700。配置上限20000约束用户输入，不约束计算后的 E。

多场景章节只调用总结模型一次完成整章分配，单场景直接取得 T。模型格式错误、窗口遗漏/重复或总数错误时采用明确标记的本地长度加权回退；供应商或网络失败仍走重试流程。最终预算为0的窗口保留原文，跳过生成调用。

最终计划及规则版本、T/M/X、分配来源、窗口初始预算与最终预算，随正文版本原子保存。生成提示词使用窗口最终预算；整章质检使用 E 和既有容差。上限限制的是分配目标，实际生成仍遵循原有质检规则。

修改 T/M/X 使未完成章节的分配失效，不重跑总结或识别。原文身份、范围及最终预算一致的成功场景可以复用；预算改变或无法证明一致时重新生成。已发布版本保持原文与原质量状态；缺少快照的历史版本走兼容读取，不套用新规则。

## 正文提示词与识别上下文

无论是否启用上下限，正文生成统一使用同一套提示词，包括“本窗口建议净增字符：N”。只替换最终预算数字；系统前后提示词、通用改写规则、当前窗口分类规则、前后文、章节总结、已审核窗口证据与输出协议不因预算上下限而改变。上下限与预算快照由程序处理，不向正文模型添加说明。M=X=0 关闭上下限，但仍使用新的模型分配逻辑，不恢复旧版长度加权分配。分配调用的提示词与正文调用相互独立。

从 1.0.0 起，正文生成不再附带整章识别结果列表：改写 AB 时只发送当前窗口的 AB 类别规则、已审核证据与预算，保留原有只读章节背景。没有窗口证据时明确显示无证据，不回退到整章列表。预算分配仍使用全部候选场景。此调整不改变合并或调用组织方式。

回归通过真实 HTTP 供应商请求，逐字比较仅移除整章识别列表后的 e2957ec 中性提示词基线。双0、最低150/最高700、最低150/无上限三种组合只允许预算数字变化，并检查模型、温度和输出容量参数。

## Android 回退说明

预算快照迁移将数据库版本升级到29。只支持28的旧APK不能直接打开升级后的数据；本地覆盖安装验证会在启动阶段报 `database schema version 29 is newer than supported version 28` 并退出。保留支持数据库29的新包，不清空或降级项目数据库。正文提示词的修正不需要安装旧版。
